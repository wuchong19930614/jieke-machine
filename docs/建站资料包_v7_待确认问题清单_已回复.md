### Q1 一条生产线是一个产品，还是包含多个型号？

**现状**：需求书第三部分写“具体型号和是否增加同类型号在录入时确认”，第六部分写“实际产品型号数由报价单明确”。原型参数表只有一列 Specification，只能放一个型号。

**影响**：数据库设计、参数表样式、网址和报价。

**可选**：

- A. 每条生产线一个页面，参数表只放一个标准配置
- B. 每条生产线一个页面，参数表多列对比几个型号，例如 100 / 300 / 500 kg/h（建议：外贸机械站常见，页面数不增加）
- C. 每个型号单独一个页面

**我的回答**：B。每条生产线一个页面，参数表多列对比几个型号。

<a id="h3"></a>

### Q2 产品详情的“相关设备”模块放什么？

**现状**：需求书已删除 Single Machines 分类，但产品详情模板仍保留 Related Equipment 模块，原型里的“Explore Equipment”按钮跳到产品列表。只剩 4 条生产线时，没有单机页面可以链接。

**可选**：

- A. 改为“相关生产线”，推荐另外 3 条线（建议）
- B. 恢复单机页面（与已删分类冲突，需另加预算）
- C. 删除该模块

**我的回答**：A。改为“相关生产线”，推荐另外 3 条线。

### Q7 是否做多语言？

**现状**：原型顶栏有“EN”，看起来像语言切换；需求书只写“正式站默认英文”，没有说是否需要其他语言。

**可选**：

- A. 只做英文，去掉“EN”
- B. 首期只做英文，架构预留多语言
- C. 首期就做多语言（请列出语种）

**我的回答**：B。现阶段只做英文，架构预留多语言；不考虑阿拉伯语，不需要从右往左的排版。

### Q8 后台“可视化编辑”做到什么程度？

**现状**：需求书要求后台能改“文字、颜色、字体、间距、背景、模块排序、显示隐藏及图框”，这相当于一个完整的页面搭建器，开发量和报价会明显上升。同一份需求书又要求“品牌色、Logo、字体和间距由朋友统一实现”，两者有冲突。

**可选**：

- A. 全站任意元素都能自由调整
- B. 在设计好的主题范围内调整：预设几套颜色、字号、间距档位，模块可排序和隐藏（建议：风格统一，成本可控）
- C. 后台只改内容，样式由开发维护

**我的回答**：B。在设计好的主题范围内调整：预设几套颜色、字号、间距档位，模块可排序和隐藏。

## 二、P1：开发中确定

这 13 个问题影响具体功能，建议在开发提交设计稿前答复。Q10–Q15 关于询盘与表单，Q16–Q22 关于页面与内容。

<a id="h12"></a>

### Q10 隐私同意勾选框是否必须勾选？

**现状**：需求书规定必填 4 项（姓名、邮箱、国家／地区、需求），表单下方放隐私说明。原型的三个表单（联系页、产品页、联系弹窗）都有一个必须勾选的“I agree to the Privacy Policy”，实际变成 5 项必填。

**可选**：

- A. 必须勾选才能提交
- B. 不放勾选框，在提交按钮下方写“提交即表示同意隐私政策”并附链接

**说明**：Q3 的目标市场会影响这个选择。

**我的回答**：B。不放勾选框，在提交按钮下方写“提交即表示同意隐私政策”并附链接。

<a id="h13"></a>

### Q11 红色客服的离线留言算不算询盘？

**现状**：需求书“统一询盘记录”只覆盖联系页、产品页和联系弹窗 3 种表单。红色客服的离线留言（原型字段：姓名、电话、邮箱、留言，没有国家）是否进询盘后台、是否发邮件通知、是否计入 generate\_lead 统计，都没有写。第九部分验收也只测“三种表单”。

**可选**：

- A. 进统一询盘后台，同样发邮件、计入统计（建议：避免漏单）
- B. 只留在客服系统里

**我的回答**：A。进统一询盘后台，同样发邮件、计入统计。

<a id="h14"></a>

### Q12 国家／地区字段用下拉还是自由填写？

**现状**：联系弹窗有 7 个建议选项（United States、United Kingdom、India、Indonesia、Thailand、Vietnam、Other），联系页和产品页表单是自由文本。需求书没有规定。

**可选**：

- A. 三个表单都用完整的国家下拉（建议：方便后台统计和筛选）
- B. 都用自由填写
- C. 下拉加可手动输入

**我的回答**：A。三个表单都用完整的国家下拉。

<a id="h15"></a>

### Q13 各表单的字段名称是否统一？

**现状**：联系页和产品页表单叫“Phone / WhatsApp”和“Your Requirements”，联系弹窗叫“Phone”和“Message”。统一询盘后台需要一致的字段。

**可选**：

- A. 统一为“Phone / WhatsApp”和“Your Requirements”（建议）
- B. 保持现状，由后台做对应

**我的回答**：A。统一为“Phone / WhatsApp”和“Your Requirements”。

### Q14 提交成功后显示提示，还是跳转感谢页？

**现状**：需求书第五部分写“成功提示只在服务端确认保存后显示”，原型是表单内提示；第一部分的网址结构又列了“提交成功页”；统计部分提到“刷新感谢页不重复计数”。用哪种方式没有定。

**可选**：

- A. 跳转独立感谢页（建议：方便以后统计广告转化）

<a id="h17"></a>

### Q15 询盘通知和跟进的细节

**现状**：需求书要求询盘保存到后台并通知业务邮箱、可标记跟进状态、防止垃圾询盘，但没有给出下面这些细节。请在各项后填写：

- 通知邮件发给哪些邮箱（一个还是多个）：**1 个**
- 是否给客户自动回复一封确认邮件：**是**
- 跟进状态有哪些（例如：新询盘 / 已联系 / 报价中 / 成交 / 无效）：**新询盘 / 已联系 / 已报价 / 成交 / 无效**

### 4.2 原型的已知问题

### 4.3 字段对应表的使用注意

CSV 与 JSON 内容一致（468 个字段、6 类重复条目），并且与后台原型运行时生成的字段清单逐字一致。需求书已声明它只是原型字段索引，建库时请注意下面几点：

1. 模块名不可靠。它是自动取所在区块第一个标题生成的：首页和产品列表 4 条生产线的 40 个字段都归在“净菜加工流水线”下；4 张 Banner 的 21 个字段都归在“Vegetable Processing Line”下；公司数据和产品详情横幅归到“公共区域”；产品详情有 51 个字段都归在“Product Introduction”下。
2. 没有“字段名称”一栏，只有前台占位文案（其中 209 条含中文）。需求书要求后台标明“前台页面、模块和字段名称”，需要另行命名，例如“Banner 标题”“公司数据 1 数值”。
3. 混入了不应作为内容字段的条目：10 条原型演示提示（例如“原型演示，不发送任何信息。”）；由脚本动态生成的“1 / 4”“播放”，改了也会被脚本覆盖；还有大量 aria-label 和 title 属性。
4. 缺少几类字段：按钮链接和 Banner 跳转地址（需求书要求可编辑）、SEO 字段、表单成功／失败提示（表中 0 条）、Banner 手机版图片、图片替代文字。
5. 联系方式不是单一来源：顶栏的“Email / WhatsApp / EN”是一整段文本，页脚、联系页、弹窗各有独立字段；首页和产品列表的生产线卡片也是独立字段，记录规则为“当前页面或公共配置”，没有引用产品记录。正式系统应按需求书做成“一处修改、全站同步”。
