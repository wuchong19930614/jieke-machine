## 一、说明

<a id="s1-1"></a>

### 1.1 范围与依据

**包含**：导航、页脚、按钮、模块默认标题、表单字段名 / 占位提示 / 校验错误 / 提交失败提示、悬浮栏、联系弹窗、红色在线服务窗口、蓝色在线沟通面板、Cookie Settings 弹窗、感谢页、404 页、空状态、询盘确认邮件，以及只给读屏软件朗读的文字（aria-label）。

**不包含**：产品、案例、公司介绍、服务项目、公司数据等业务内容；隐私政策和 Cookie 说明正文（见《隐私政策与Cookie说明模板（含巴西LGPD）》）。

**依据文件**：

- `latiao-prototype-v18.html`：根目录版与 `source/` 版的界面文字已逐条比对，内容一致。
- `机械设备独立站正式建站需求书_v7.docx`：第一至第五部分的页面、悬浮栏、弹窗、客服、询盘要求。
- `前后台字段对应表_v18.csv`：原型每个文字字段的编号和原文。
- `机械设备独立站技术方案.md`：3.2 全站设置、4.2 公共组件、4.5 表单与客服、6.1 提交询盘接口、7.3 Cookie 设置、7.4 视频。
- `建站资料包_v7_待确认问题清单_已回复.pdf`：Q2、Q6、Q7、Q10–Q14、Q16–Q22、Q24 的答复。

**写入位置**：按技术方案 3.2 节，这些文案存在后台“全站设置”（navLabels、floatingTools、formTexts、redPanelTexts、bluePanelTexts、whatsappMessage、autoReplySubject、autoReplyBody 等）和各页面配置里，作为默认值预填，业务方可以修改。技术方案第四部分要求代码里不写死文案，因此读屏文字（aria-label）也建议放进后台的通用文案组，至少不能保留原型里的中文。

<a id="s1-2"></a>

### 1.2 条目格式与来源标记

每个条目写：位置、中文含义、英文文案、来源、备注。“来源”列的含义：

- **原型**：原型已有英文，核对后语法和语气没有问题，原样使用。
- **原型·改**：原型已有英文，建议修改。备注写出原文和修改理由。
- **原型·译**：原型是中文或占位，这里给出英文。
- **补充·方案**：原型里没有，依据技术方案、需求书或问题清单答复补充。备注写出依据章节。
- **补充·建议**：原型和各文件都没写，按 B2B 外贸网站的常规做法补充。是否采用由业务方确认。
- **补充·需求书**：原型和技术方案都没写，按需求书原文补充。备注写出依据。
- **—**：业务内容，只标出位置，不给英文，由业务方录入。

<a id="s1-3"></a>

### 1.3 书写规范

1. **拼写**：统一用美式英语（inquiry、customize、color），不用英式写法 enquiry。
2. **大小写**：导航、模块标题、按钮、表头用标题大小写（实词首字母大写，短介词和冠词小写，如 Talk to Our Team）；正文、提示、占位、报错用句子大小写（只有句首大写）。
3. **小标题（kicker）**：页面上显示为全大写。建议后台按正常大小写保存，前台用 CSS 转成大写，读屏软件不会逐个字母念。本文件按页面显示效果写成全大写。
4. **箭头**：提交类按钮（Send Inquiry、Send Message、Save Settings）不加箭头；其余按钮和链接沿用原型写法。
5. **符号**：省略号用单个字符“…”；撇号用直撇号 '；数字千位加逗号（5,000）；单位写在括号里，如 Capacity (kg/h)。
6. **变量**：用 `{变量名}` 表示，由系统替换。变量为空时，所在的整行或整句不显示。常用变量：`{companyName}` 公司名、`{businessEmail}` 业务邮箱、`{phone}` 电话、`{whatsapp}` WhatsApp 号码、`{productName}` 产品名、`{caseTitle}` 案例标题、`{n}` 序号、`{total}` 总数、`{year}` 当前年份。均取自全站设置或当前记录。
7. **新窗口**：WhatsApp、社交媒体、YouTube 链接在新窗口打开，并给读屏软件加一句隐藏文字 “(opens in a new tab)”。
8. **字数**：备注里的字数指英文字符数（含空格），是为了保证手机上不换行或不溢出的建议上限。


<a id="s17-2"></a>

### 17.2 变量与发送规则

变量（名称为建议，开发确认）：

- `{name}`：客户填写的姓名。
- `{aboutProduct}`：产品页询盘时为 “ about {productName}”（前面带空格），其他来源为空。
- `{companyName}`、`{businessEmail}`、`{phone}`、`{whatsapp}`：取全站设置；为空的联系方式整行不写。
- `{websiteUrl}`：网站正式地址（环境变量 NEXT_PUBLIC_SITE_URL）。

发送规则：

1. 回复地址设为业务邮箱，客户直接点“回复”即可补充信息（技术方案 7.1），所以正文写 “simply reply to this email”。
2. **不回显客户填写的需求正文和公司名。** 自动回复会发到访客填写的任意邮箱，这个邮箱没有经过验证；如果邮件里原样带上访客输入的内容，别人可以借网站向任意邮箱发送垃圾内容。邮件里只用姓名和系统里的产品名。
3. 姓名如果含网址（如 http、www），称呼改为 “Hello,”，不带姓名；姓名已限制 100 字符，并按技术方案 9.1 转义。
4. 命中陷阱字段或填写过快的提交不保存，也不发确认邮件（技术方案 6.1）。
5. 发送失败时由定时任务重发（技术方案 6.4），文案不变。
6. 同时提供 HTML 和纯文本两个版本，文字相同。
7. 发给业务人员的内部通知邮件给公司内部看，建议用中文，不在本文件范围。
