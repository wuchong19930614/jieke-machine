阶段一 · 准备

第 0 步先拍板两件事

谁来做：业务方 ｜ 影响：选错了以后要迁移账号

  1. 决定 Vercel 用免费版还是 Pro。 按 Vercel 的定义，本站展示产品、收集询盘，开发也是付费的，属于商用；免费版（Hobby）条款只允许个人非商用，Vercel 可以不经通知停掉免费版项目（技术方案 10.4 节）。建议直接用 Pro：每月 20 美元起，含 20 美元用量额度，每个团队成员席位 20 美元/月（技术方案 10.3 节）。代码不用改。决定用 Pro 的话，先在 Vercel 升级或新建 Pro 团队，再做第 5 步导入项目，省得以后迁移。
  2. 给 Turso 发邮件要书面确认可以商用。 Turso 的条款没有写明允许商用（技术方案 10.4 节）。发邮件给 Turso 支持，说明是公司官网、用免费版，请对方书面确认，回信存档。不影响后面的步骤，可以同时进行。

第 1 步开通账号

谁来做：业务方 ｜ 全部用公司邮箱注册，账号归公司所有（技术方案第七章）

  1. GitHub：代码已经在 wuchong19930614/jieke-machine。确认仓库是私有（Private）。Vercel 账号最好和这个 GitHub 账号是同一个人，自动部署最省事；开发者不是 Vercel 账号成员时，推代码能否自动部署 未确认（技术方案 10.3 节）。
  2. Vercel（vercel.com）：用上面那个 GitHub 账号登录注册。
  3. Turso（turso.tech）：数据库，免费版。
  4. Resend（resend.com）：发邮件，免费版每月 3,000 封、每天 100 封。
  5. tawk.to：在线客服，免费版。
  6. Google 账号：用于 Google Analytics（GA4）、Google Tag Manager（GTM）、Search Console，都免费。

第 2 步建正式数据库（Turso）

在哪做：Turso 控制台 ｜ 得到：数据库地址、数据库令牌

  1. 新建数据库，名字建议 jieke-prod。区域选欧洲爱尔兰（aws-eu-west-1，以控制台可选项为准），和网站服务器（都柏林）同城，速度最快。
  2. 复制数据库地址，以 libsql:// 开头，填到第 7 步的 DATABASE_URI。
  3. 生成令牌（Create Token），权限选可读写、不过期，复制保存，填到第 7 步的 DATABASE_AUTH_TOKEN。令牌只显示一次，立刻存进密码管理工具。

装了 Turso 命令行工具的话，也可以用命令查地址和生成令牌：

turso db show jieke-prod --url
turso db tokens create jieke-prod
注意Turso 免费版任一额度超限会直接封库；数据库闲置 10 天会被归档（网站上线后每天的备份会读库，可以避免归档）。所以建好库后尽量在 10 天内完成部署。

第 3 步生成 5 个密钥

在哪做：自己电脑的终端 ｜ 得到：5 串随机字符

下面这条命令每运行一次，生成一串 64 位的随机字符。运行 5 次，分别用作 5 个密钥，每个都不一样：

openssl rand -hex 32
  1. PAYLOAD_SECRET：后台登录加密。以后换掉会让所有人重新登录。
  2. BACKUP_ENCRYPTION_KEY：备份加密。除了存进密码管理工具，还要在线下另存一份（打印或存 U 盘）。丢了这个密钥，所有备份都解不开。
  3. CRON_SECRET：定时任务调用密钥，Vercel 调用定时任务时会自动带上。
  4. PREVIEW_SECRET：后台草稿预览用。
  5. IP_HASH_SECRET：询盘里访客 IP 的加密。不填也能用（会由 PAYLOAD_SECRET 派生），建议单独填。

第 4 步配置发信域名（Resend）

在哪做：Resend 控制台 + 域名注册商 ｜ 得到：发信 API Key

为什么要先做Resend 没认证域名时，只能发信给 Resend 账号本人，客户收不到自动回复，公司也收不到询盘通知。解析记录生效要时间，所以先做。
  1. 添加域名：Resend 控制台 › Domains › Add Domain，填 jetcomachinery.com。如果让选发信区域，选欧洲（Ireland）即可。
  2. 去域名注册商加解析记录：Resend 会列出几条记录（SPF 和 DKIM，类型是 TXT 和 MX），照着一条一条加到域名的解析设置里。
  3. 再加一条 DMARC 记录（减少进垃圾箱，技术方案 7.1 节）：类型 TXT，主机名 _dmarc，值先填下面这行： 
    v=DMARC1; p=none;
  4. 回 Resend 点 Verify，等域名状态变成 Verified（已验证）。
  5. 生成 API Key：API Keys › Create API Key，权限选 Sending access（只能发信），域名选 jetcomachinery.com。只显示一次，复制保存，填到第 7 步的 RESEND_API_KEY。
完成标志Resend 里 jetcomachinery.com 显示已验证，手里有一个 API Key。
阶段二 · 部署

第 5 步创建 Vercel 项目

在哪做：Vercel 控制台

  1. 导入仓库：Add New › Project，选 GitHub 上的 jieke-machine。框架会自动识别为 Next.js；构建命令、区域和定时任务已经写在仓库的 vercel.json 里，不用改。
  2. 导入页面上不要填环境变量，直接点 Deploy。那里填的变量会同时用到正式和测试环境，容易让测试环境连上正式库。
  3. 第一次部署失败或网站打不开都是正常的，因为还没配数据库。配好后在第 10 步重新部署。
  4. 确认 Node.js 版本：Settings › Build and Deployment › Node.js Version 应为 24.x（代码里已声明 24.x，一般会自动选上）。

第 6 步创建两个文件存储（Vercel Blob）

在哪做：Vercel 项目 › Storage ｜ 得到：两个存储令牌

  1. 图片存储（公开）：Storage › Create › Blob，名字建议 jieke-media-prod，访问方式选 Public（公开）。网站上的图片、PDF 手册都放这里。
  2. 备份存储（私有）：再建一个 Blob，名字建议 jieke-backup-prod，访问方式选 Private（私有）。备份里有后台账号的密码哈希，必须私有。
  3. 把令牌对上变量名，最后要做到：正式环境（Production）里有且只有这两个变量——
    • BLOB_READ_WRITE_TOKEN = 公开图片存储的令牌
    • BACKUP_BLOB_READ_WRITE_TOKEN = 私有备份存储的令牌
    连接存储时 Vercel 会自动建一个变量，名字不一定对得上 未确认。对不上就删掉自动建的，到存储页面复制令牌（以 vercel_blob_rw_ 开头），在第 7 步手动添加。连接时只勾 Production 环境。
别搞反两个令牌填反的话，图片会传到私有存储（前台显示不出来），备份会传到公开存储（任何人拿到地址都能下载）。

第 7 步填写正式环境变量

在哪做：Vercel 项目 › Settings › Environment Variables

每个变量添加时，环境只勾 Production，不要勾 Preview 和 Development。建议打开 Sensitive（敏感），打开后就看不到原值了，所以先确认已存进密码管理工具。

变量名填什么从哪来
DATABASE_URI正式库地址，libsql:// 开头第 2 步
DATABASE_AUTH_TOKEN正式库令牌第 2 步
NEXT_PUBLIC_SITE_URLhttps://www.jetcomachinery.com（不带结尾斜杠）固定值
PAYLOAD_SECRET随机字符第 3 步
BACKUP_ENCRYPTION_KEY随机字符（必须正好 64 位）第 3 步
CRON_SECRET随机字符第 3 步
PREVIEW_SECRET随机字符第 3 步
IP_HASH_SECRET随机字符第 3 步

BACKUP_BLOB_READ_WRITE_TOKEN私有备份存储的令牌第 6 步

MAIL_FROM发件人，例如 Jieke Machinery <noreply@jetcomachinery.com>，尖括号前换成公司英文名自己定
  • TURNSTILE_SECRET_KEY 先不填，以后垃圾询盘多、要开人机验证时再填。
千万不要加TOTP_DISABLED。它是本地调试时关掉后台双重验证用的。
  1. 按表格逐个添加 12 个变量，每个都只勾 Production。
  2. 核对一遍：Production 环境里正好是表格中的 12 个变量，名字一个字母都不能错，没有 TOTP_DISABLED。

第 8 步绑定域名

在哪做：Vercel 项目 › Settings › Domains + 域名注册商

  1. 添加 www.jetcomachinery.com（这是正式地址）。
  2. 再添加 jetcomachinery.com。如果 Vercel 问要不要把它跳转到 www，选跳转（永久 308）；不选也行，网站代码会自动把不带 www 的地址 308 跳到 www。
  3. 去域名注册商加解析记录：按 Vercel 页面显示的记录类型和值添加（一般不带 www 的是 A 记录，www 是 CNAME）。注册商默认带的 @ 和 www 停放记录要先删掉。可以和第 4 步的 Resend 记录一起加。
  4. 等 Vercel 显示配置有效，证书由 Vercel 自动申请。解析生效可能要几分钟到几小时，取决于注册商。
为什么要在建管理员之前做后台只认 NEXT_PUBLIC_SITE_URL 这个地址。域名没生效时，用 Vercel 自带的 .vercel.app 地址打开后台，保存等操作会被当成没登录。

第 9 步设置防火墙限流

在哪做：Vercel 项目 › Firewall ｜ 作用：挡住机器人刷询盘，保护 Turso 免费额度

新建一条规则（免费版每个项目只能建 1 条，就用这一条），按技术方案 4.5 节：

  1. 条件：请求路径（Request Path）等于 /api/inquiries，或者请求路径等于 /api/form-token。
  2. 动作：限流（Rate Limit），固定窗口 60 秒，每个 IP 最多 10 次；超出时返回 429（Too Many Requests）。
  3. 保存并发布（Vercel 防火墙规则保存后还要点发布才生效）。

第 10 步重新部署并确认成功

在哪做：Vercel 项目 › Deployments

  1. 重新部署：找到最新一次部署，点右侧 ⋯ › Redeploy。环境变量改了必须重新部署才生效。
  2. 看构建日志：先执行 payload migrate（自动建表），再执行 next build，最后显示部署成功。
  3. 打开网站：访问 https://www.jetcomachinery.com 能看到首页（没录内容的模块会自动隐藏）；访问 https://jetcomachinery.com 会自动跳到带 www 的地址。
部署成功后马上做第 11 步中间不要停。
阶段三 · 后台初始化

第 11 步立刻注册第一个管理员

在哪做：https://www.jetcomachinery.com/admin

最容易踩的坑数据库里还没有账号时，第一个打开后台注册的人自动成为管理员（代码 src/collections/Users.ts 第 39–44 行）。所以部署成功后要立刻自己注册，不能拖。
  1. 打开后台，填写第一个账号：用公司邮箱，密码至少 12 位。这个账号自动是管理员。
  2. 设置双重验证：第一次登录会强制进入设置页，用手机验证器 App 扫码，再输入 6 位验证码（后台操作教程 1.1 节）。
  3. 给同事开账号：系统 › 用户 › 新建，选角色：管理员、内容编辑、业务人员或开发协作（后台操作教程 1.2 节）。把后台地址和初始密码告诉对方，对方第一次登录时自己设置双重验证。
如果打开后台看到的是登录页而不是注册页说明已经有人先注册了。马上停下来联系开发人员处理，不要继续往下做。

第 12 步填写全站设置

在哪做：后台 › 全站设置（详见后台操作教程 9.1 节）

  1. 品牌：公司英文名、Logo、页脚简介。
  2. 联系方式：业务邮箱、电话、WhatsApp（都带国际区号，如 +86 138 0000 0000）、地址、办公时间。
  3. 询盘邮件：填询盘通知邮箱（不填就收不到新询盘通知）和发给客户的自动回复内容。
  4. 社交媒体：各平台账号链接，显示在页脚。
  5. 默认 SEO 与网站图标：默认标题和描述、默认分享图（1200×630）、网站图标、苹果触屏图标。
  6. “统计、收录与安全”里的“允许搜索引擎收录”先不要勾，等内容录完再开（第 18 步）。
  7. 保存，然后点发布。tawk.to 和 GTM 编号在第 13、14 步拿到后再回来填。

第 13 步接入在线客服（tawk.to）

在哪做：tawk.to 后台 + 网站后台 › 全站设置 › 在线客服

  1. 新建站点（Property），网址填 https://www.jetcomachinery.com。
  2. 找到两个编号：Administration › Chat Widget 里能看到 Property ID 和 Widget ID（直接聊天链接 https://tawk.to/chat/Property ID/Widget ID 里也有）。
  3. 给每位客服开独立账号，客服可以用电脑或 tawk.to 手机 App 接待。可以在对话窗口外观里设置品牌色和 Logo。
  4. 回网站后台填编号：全站设置 › 在线客服（tawk.to），填 Property ID 和 Widget ID，保存并发布。

不用在 tawk.to 里设置离线留言：客服离线时，网站会显示自己的留言表单，留言进后台“询盘”（技术方案 7.2 节）。

第 14 步接入统计（GA4 + GTM）

在哪做：Google Analytics、Google Tag Manager + 网站后台 ｜ 网站只往 GTM 推事件，GA4 在 GTM 里配置（技术方案 7.3 节）

A. 建 GA4

  1. 新建媒体资源和网站数据流，网址填 https://www.jetcomachinery.com，复制“衡量 ID”（G- 开头）。
  2. 关闭 Google 信号：管理 › 数据收集和修改 › 数据收集，关闭 Google 信号数据收集。
  3. 关闭广告个性化：同一页的高级设置里，关闭所有地区的广告个性化；也不要关联 Google Ads。
  4. 数据保留期设为 14 个月：管理 › 数据收集和修改 › 数据保留。

上面这 3 项设置是首期不弹 Cookie 同意横幅的前提（技术方案 7.3 节），必须做。菜单名以实际页面为准。

B. 建 GTM 并配置

  1. 新建账号和容器（类型选“网站”），复制容器编号（GTM- 开头）。
  2. 加 Google 代码：新建代码（Tag），类型选 Google 代码，代码 ID 填 GA4 的 G- 编号；触发器选 Initialization - All Pages。
  3. 建 9 个数据层变量：变量 › 新建 › 类型选“数据层变量”，数据层变量名分别填： 
    form_source
product_name
inquiry_ref
location
entry
metric_name
metric_value
metric_rating
metric_id
  4. 建一个触发器：类型选“自定义事件”，勾选“使用正则表达式匹配”，事件名称填： 
    ^(generate_lead|click_email|click_phone|click_whatsapp|open_chat|start_chat|download_brochure|web_vitals)$
  5. 建一个 GA4 事件代码：类型选 Google Analytics: GA4 Event，衡量 ID 填 G- 编号，事件名称填 {{Event}}；事件参数逐个添加上面 9 个，参数名和变量一一对应（如参数 form_source 的值选 form_source 那个数据层变量）；触发器选上一步那个。
  6. 提交并发布容器。
  7. 回网站后台填编号：全站设置 › 统计、收录与安全 › GTM 容器编号，填 GTM- 编号，保存并发布。
  8. 把询盘设为关键事件：GA4 › 管理 › 数据显示 › 事件（或“关键事件”），把 generate_lead 标为关键事件。事件要先收到一次才会出现在列表里，也可以直接新建同名的关键事件。
注意GTM 里先只放 GA4。以后要加广告或其他第三方代码，要先让开发把对应域名加进网站的安全策略（next.config.ts），否则会被浏览器拦截。

第 15 步导入隐私政策和 Cookie 说明

在哪做：自己电脑的终端（项目目录）+ 网站后台 ｜ 前提：第 12 步的全站设置已发布（公司名和地址会自动填进去）

  1. 在项目目录下运行导入命令，把引号里的两处换成第 2 步的正式库地址和令牌： 
    DATABASE_URI="libsql://换成正式库地址" DATABASE_AUTH_TOKEN="换成正式库令牌" NEXT_PUBLIC_SITE_URL="https://www.jetcomachinery.com" npm run import:legal -- --allow-remote
    成功时会显示 Privacy Policy 和 Cookie Notice 都已新建、存为草稿，并列出还要补齐的占位符。
  2. 在后台补齐占位符：页面管理 › 辅助页面，分别打开隐私政策和 Cookie 说明，把方括号里的待填内容和法务确认后替换（后台操作教程 4.4 节）。导入时剩下的有：
    • 隐私政策：[privacy@example.com]（隐私联系邮箱）、[DPO name]（数据保护负责人）、[Inbox retention]、[Chat retention]（邮箱和聊天记录的保存期限）、[Country]、[Confirm the transfer mechanism for each provider before publishing.]（跨境传输依据）
    • Cookie 说明：[As set by tawk.to]、[As set by YouTube]（两家 Cookie 的保存期限）、[privacy@example.com]
  3. 两页都替换完后点“发布修改”。
不会改正式库的表结构连 Turso 远程库时，系统已设为不自动同步表结构（src/payload.config.ts 里的 push 设置），脚本只写入这两页内容，表结构只由 Vercel 部署时的数据库升级来改。
另外永远不要对正式库运行 npm run seed。它会写入示例数据和三个本地测试账号，测试账号的密码就写在代码里。
阶段四 · 测试与上线

第 16 步全面测试

在哪做：正式网站 ｜ 这时搜索引擎还不会收录，可以放心测试。这些功能目前都只在本地验证过，还没连真实账号测过（README 第十章）

  1. 4 种询盘表单各提交一次：联系页表单、产品页表单、联系弹窗、客服离线留言。每次检查：后台“询盘”里有记录，来源和产品正确；询盘通知邮箱收到通知；客户邮箱收到自动回复。
  2. 邮件进不进收件箱：客户邮箱分别用 Gmail、Outlook 和公司邮箱测，确认进的是收件箱，不是垃圾箱（技术方案 7.1 节）。
  3. 测完把测试询盘改成“无效”（后台操作教程第十二章）。
  4. 图片：在媒体库上传一张图，用到某个页面上发布，前台能正常显示。
  5. 在线客服：客服在线时，从网站发起对话，tawk.to 后台能收到消息和附件；客服离线时留言，留言进后台“询盘”。
  6. 统计：打开 GA4 实时报告，提交一条询盘，generate_lead 只出现 1 次；刷新感谢页不会重复计数。
  7. 草稿预览：改一处内容只保存草稿，点预览能看到修改，前台正式页面不变。
  8. 业务人员账号：用业务人员账号登录，从前台点“定位”到一条没有编辑权限的内容，应该被拦下或提示无权限（README 第十章：这一项还没在浏览器里实测过）。
  9. 后台操作教程：打开 https://www.jetcomachinery.com/admin/guide，能看到教程内容。
  10. 手机端：用手机打开网站看一遍。右侧悬浮栏现在默认收起成一个按钮，这个改动待业务方确认，不接受就告诉开发改回常驻一列。

第 17 步检查定时任务和备份（部署后第二天）

在哪做：Vercel 项目 › Settings › Cron Jobs + 网站后台 › 系统 › 备份记录

  1. 确认有两个定时任务：/api/cron/backup（每天 UTC 02:00 这一小时内，即北京时间 10:00–10:59）和 /api/cron/maintenance（UTC 03:00 这一小时内，即北京时间 11:00–11:59）。
  2. 第二天中午以后看备份记录：后台 › 系统 › 备份记录里有当天的数据库备份和媒体备份，状态成功。失败时管理员也会收到提醒邮件。
  3. 请开发人员演示一次恢复：从备份记录下载一份备份，解密后导入一个新数据库，确认数据完整（README 第七章、技术方案 9.2 节）。

第 18 步上线当天：开放收录

前提：首页、关于我们、产品、案例、联系我们的英文内容都已录入并发布

  1. 验证 Search Console：添加资源，类型选“网域”，填 jetcomachinery.com，按提示在域名解析里加一条 TXT 记录，然后验证。
  2. 对照上线检查：后台操作教程第十二章的 5 项：内容已发布、隐私政策和 Cookie 说明已补齐并发布、联系方式和询盘邮件已填并测过、分享图和网站图标已上传。
  3. 开放收录：后台 › 全站设置 › 统计、收录与安全，勾选“允许搜索引擎收录”，保存并发布。
  4. 检查两个文件：打开 https://www.jetcomachinery.com/robots.txt，应该允许抓取；打开 https://www.jetcomachinery.com/sitemap.xml，应该列出已发布的页面。
  5. 提交网站地图：Search Console › 站点地图，填 sitemap.xml 提交。

附录 A测试环境（建议做，不影响上线）

用途：以后改功能先在测试站验收，不碰正式数据（技术方案 2.2 节）

  1. 准备测试资源：Turso 再建一个库 jieke-test；Vercel Blob 再建一个公开、一个私有存储，用于测试；第 3 步的 5 个密钥为测试环境另外生成一套。
  2. 建一个测试分支并推送：推送后 Vercel 会为它生成预览部署和一个固定的分支地址（地址里带 -git-test-）。 
    git checkout -b test
    git push -u origin test
  3. 填 Preview 环境变量：变量名和第 7 步一样，值换成测试用的，环境只勾 Preview。NEXT_PUBLIC_SITE_URL 填上面那个分支地址；不填的话测试站后台的保存、上传都会被当成没登录。
  4. 开启部署保护：Settings › Deployment Protection › Vercel Authentication。测试站只有登录了 Vercel 并获批的人能看；也可以生成共享链接给业务方审核。
  5. 测试库同样要马上注册第一个管理员（同第 11 步）。
